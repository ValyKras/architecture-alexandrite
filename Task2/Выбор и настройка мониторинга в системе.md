## Мотивация
Мониторинг необходим компании в первую очередь для того, чтобы определять, на каком из этапов работы системы происходят сбои. Это позволит не тратить время специалистов для глубокого анализа системы (произойдет снижение времени обнаружения инцидентов), а вместо этого, потратить время на решение проблемы. Так же позволит конролировать SLA и принесет больше прозрачности для бизнеса. 

## Выбор подхода к мониторингу
1. Для API/сервисов подходит RED
2. Для пользовательского взаимодействия -  «Четыре золотых сигнала»

## Выбранные метрики и назначение
- Number of HTTP 500 — выявление сбоев сервисов (API магазина, CRM, MES); ярлыки: service, endpoint.
- Response time (latency) — найти медленные запросы (API магазина, CRM, MES); ярлыки: service, endpoint.
- Number of requests (RPS) — оценка нагрузки (API магазина, CRM, MES); ярлыки: service, user_type.
- Number of message in flight и dead‑letter — контроль надёжности асинхронной обработки, каждое такое сообщение — потерянный заказ, алерт при значении больше нуля.; ярлыки: queue, exchange.
- CPU %, Memory Utilisation — выявление перегрузки инстансов (Инстансы приложений и БД); ярлыки: service, instance_id.
- Number of connections для БД — предотвращение исчерпания пула соединений; ярлыки: db_instance.
